# Vikunja X · tcymc二次开发版

基于 [Vikunja 官方 v2.7.1](https://github.com/go-vikunja/vikunja/releases/tag/v2.7.1) 的个人任务管理扩展，由 **KanameMadoka520** 维护。保留上游项目、任务、甘特图、看板、提醒、CalDAV 和 MCP，增加可配置模型的 AI 助手、语音输入和独立公开主页。

- 源码与问题反馈：[KanameMadoka520/vikunja-x](https://github.com/KanameMadoka520/vikunja-x)
- 版本：`v2.7.1-tcymc.16`
- 许可证：AGPL-3.0-or-later；上游版权和许可证继续适用，参见 [LICENSE](LICENSE) 与 [上游 README](README.upstream.md)。本项目是独立二次开发版。


## 任务层级的可视化（tcymc.16）

列表以连接线、缩进和展开／收起按钮展示父子层级；列表、看板、表格及复用任务行的总览直接显示上级任务链接和直属子任务完成数。看板和表格可原地展开子任务名称，不必先打开详情。统计依据子任务的完成状态，与手动设置的任务进度独立，完成子任务不会自动完成上级。

一个任务有多个上级时，列表按稳定顺序选择一处摆放，同时保留全部可见上级链接，不复制任务行。筛选、分页或跨项目导致上级不在结果中时，子任务仍独立显示。历史循环关联仅在展示时打断，不修改真实关系。普通“相关”、依赖等关联不会被当成父子层级。

添加或删除关联后同步刷新两端关系提示，保留看板已经加载的分页。复用 API 权限过滤后的关系数据，不为每张卡片追加请求，不展示无权访问的任务名称。

## 附件上传百分比与网速（tcymc.15）

附件区域与全站上传面板显示浏览器报告的真实字节进度、已上传／总大小、当前传输速度和用时。任务弹窗内也有独立可见的上传状态，不会被弹窗遮住。上传完成后保留 100% 与平均传输速度，可手动清理记录。

文件传输到 100% 后，服务器校验和保存仍显示为单独的“处理中”阶段，等待响应后才显示完成。服务器处理时间不计入平均传输速度；无法获取总大小时不虚构百分比。失败与取消独立显示，HTTP 成功但附件部分保存失败也不会误标为全部完成。采样仅在活动请求期间运行，结束或取消后清理计时器。

## 任务进度的设置与移除（tcymc.14）

任务详情的进度选择框旁新增“移除进度”：将进度恢复为 0 并收起进度栏，列表和看板的进度条同步消失，可随时通过“设置进度”重新添加。进度与任务完成状态独立，移除进度不会将任务标记为未完成，也不会修改描述、日期或其他字段。保存期间阻止重复提交；失败时保留原进度、提示错误，允许重试。只读共享任务不提供移除操作。

## 一键截图脱敏（tcymc.13）

项目页顶部的“眼睛斜线”按钮打开脱敏截图预览：项目名、任务内容、个人身份、日期等业务文字替换为示例内容，上传图片和背景替换为占位图。保留列表、看板等当前界面的结构、图标和配色。

预览只生成当前页面的只读展示副本，不改 Vue 状态、编辑器、服务器数据或权限，不发送保存请求。“关闭脱敏，恢复原内容”或 Esc 可立即回到原页面，保留编辑内容与滚动位置。该功能用于屏幕截图，不是数据导出或公开分享权限机制。

## 封面、附件与描述保存（tcymc.13）

- **取消封面**只清除封面选择，保留附件和描述中的图片；**删除附件**会在确认窗口说明影响，并在同一事务中清理该任务描述、评论里的对应图片和封面引用。网盘原文件继续保留供复用，旧附件共用的文件不会被误删。
- 描述和封面操作只提交自己修改的字段；自动保存期间继续输入不会丢失新文字，失败会保留草稿并显示错误。旧页面再次保存时，服务器会过滤本任务已经删除的附件图片引用。
- 删除处理中显示加载状态并阻止重复提交；删除失败保持确认窗口，便于重试。临时无法加载的图片显示可理解的占位提示，保留原地址，避免将临时网络故障当成永久删除。
- 预设项目封面生成期间切换项目不会把封面上传到错误项目；重复选择同一个文件也可以正常上传。桌面、手机端通过实际浏览器回归验证。

## 邮箱与网站发信配置（tcymc.12）

- **设置 → 修改邮箱** 显示当前收件地址，待确认的新邮箱与当前地址分开显示；邮件提醒开关仍在常规设置中。
- **设置 → 网站发信（SMTP）** 提供服务器、端口、认证方式、发信地址、密码和 TLS 设置。仅服务器环境变量 `TCYMC_SETTINGS_ADMIN_IDS` 中明确列出的账户 ID 能访问，例如 `2,5`；普通用户没有入口，接口同样拒绝访问，API token 和公开分享不可使用。此名单仅授权本二次开发版的网站配置，不授予上游许可控制的管理面板权限。
- 初次读取现有 `VIKUNJA_MAILER_*` 环境配置；首次保存后使用数据目录中的 `.tcymc-smtp.enc` 加密配置。需备份该文件及原 `VIKUNJA_SERVICE_SECRET`。密码不回传，留空保留；更换服务器或用户名需重填密码。保存采用版本冲突检测、原子文件替换和内存快照，重启保留，下一封邮件使用新连接。保存本身不发送测试邮件。
- AI 模型设置保存失败会保留草稿并显示具体错误，后台刷新不覆盖正在编辑的内容。成功时采用服务器返回配置、清空密钥输入框；更换 API 地址需重新输入密钥，页面给出明确提示。

## 服务器负载（tcymc.12）

侧栏监控统一为整台 Linux 主机：CPU 使用率与逻辑核心数、整机内存（MemTotal − MemAvailable）、最近 1／5／15 分钟系统平均负载、数据分区占用。服务器开机时长与 Vikunja 进程运行时长分别显示，版本可点击进入对应 Release。CPU 使用总时间差计算，扣除空闲与 I/O 等待，guest 不重复计数；展开说明可查看 I/O wait 和 steal。指标语义参考 [Linux 内核 proc 文档](https://docs.kernel.org/filesystems/proc.html)。

Docker 部署合并 [只读主机指标 Compose 配置](deploy/compose.host-status.yml)，将主机 `/proc/stat`、`meminfo`、`loadavg`、`uptime` 四个文件分别挂载至 `/run/tcymc-host-proc/`。无需 Docker socket、特权模式或整个主机目录。缺少挂载时明确显示主机指标未接入，不把容器或进程用量冒充整机数据。当前部署的数据目录与服务器根分区在同一文件系统；磁盘不合并其他独立挂载点。15 秒全局缓存，侧栏和标签页可见时通常 30 秒刷新，不做文件扫描。绿色状态仅表示 Vikunja 依赖服务正常，不是整机压力判断。只对登录用户会话开放，公开分享和 API token 不可读取。

## 压缩可靠性与页面语境修复（tcymc.10）

- 项目菜单与项目背景只跟随项目和任务详情，离开项目进入 AI 助手、网盘、近期任务、个人设置等页面时清除；返回缓存中的项目页会恢复正确项目，后台刷新不再覆盖全局页面状态。项目背景及其菜单源自官方 v2.7.1，本分支补充的是封面预设、网盘复用和上传格式选择。
- 压缩从上次成功摘要继续处理新增消息，根据模型上下文容量安排历史片段，生成简明交接摘要，模型调用使用该连接的输出额度，不再写死 4,096 tokens。明确发生输出上限截断时仅重试一次，请求更简明的摘要，但不会调低配置的输出额度；其他失败不会自动反复调用。
- 显示当前批次、尝试次数、服务商报告的 token 用量和耗时。压缩诊断可导出协议、端点、模型、HTTP 状态、终止原因、请求 ID 和各轮用量，包含失败尝试；默认不导出聊天正文或模型思考文本。支持重试，失败不会用残缺摘要覆盖旧摘要，原始会话始终保留。
- 为流式与非流式截断、有限重试、旧摘要复用、诊断导出及桌面／手机实际点击跳转增加回归测试。本地编译发布，不使用 GitHub Actions。

## 模型能力与容量配置

参考 [DeepSeek Harness 模型设置](https://github.com/deepseek-ai/deepseek-harness/tree/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/client/ui-settings-models) 的分层设计，将模型能力放在连接的折叠选项中，与执行段的工具次数／权限预算分开。实现按本仓库 Vue／Go 架构编写，没有引入 Harness 运行服务。

- 可填写上下文窗口、单次最大输出 tokens、文字／图像能力，以及 OpenAI Chat 的输出额度参数兼容选项。保存后显示服务器实际采用的值，普通对话和压缩都采用相同的模型输出配置；输出额度是上限，不是要求模型生成到该长度。
- 模型目录同时读取上游提供的容量与输入类型。点击“采用模型目录中的能力参数”导入当前模型，仍可手动覆盖；未提供的字段不会编造，也不会在刷新目录时覆盖手动配置。
- 根据 2026-10-27 DeepSeek 官方 `/models` 的实际返回，官方 `deepseek-flash` 与 `deepseek-v4-pro` 的默认上下文为 1,048,576 tokens，最大输出为 393,216 tokens；Flash 声明支持文字／图像。只有官方域名采用此默认，任意同名代理模型不据此推断能力。官方 Anthropic 连接获取模型时使用同域 `/models`，不再请求不存在的 `/anthropic/models`。
- 未知模型输出填 0 时，OpenAI／Responses／Gemini 不主动发送输出上限；Anthropic 因协议要求采用可覆盖的 128,000 默认值，参考 Harness 的通用适配器默认。服务商若要求更低或更高额度，请按其实际能力修改。
- 上下文容量用于压缩分批，并在调用详情中与服务商报告的最近输入量一起展示。不把字符数冒充 token 数，不再以历史内容 400,000 字节作为强制压缩条件。模型输入能力属于上游能力声明，不代表自动增加了独立的聊天传图功能。

## 个人网盘、文件复用与封面预设

左侧「我的网盘」集中展示你的上传文件，支持名称搜索、置顶、分类、分页、缩略图及下载。任务附件、任务正文插图、项目封面均可从网盘选择，创建引用时复用同一个存储文件。附件、上传封面和头像会自动进入个人网盘；升级时把仍在使用的历史用户上传纳入网盘，不导入导出包或匿名分享上传。分类为可自定义名称的单层分类。

网盘仅对文件所有者开放。文件附加到共享任务后，能阅读任务的成员仍可正常访问附件，但不能浏览所有者的其他网盘文件。使用位置会列出任务附件／正文图片、任务封面、项目封面和头像；已失去权限的引用只显示受限提示，不暴露私有标题。

- 删除任务附件仅解除引用，网盘原件保留；更换项目封面和头像也不会删除已纳入网盘的旧文件。
- 「移入回收站」不破坏已有引用，但禁止新建引用；仍在使用的文件需先查看位置并勾选二次确认。回收站继续占用存储，支持恢复。
- 「彻底删除」只在回收站内提供。必须先解除所有引用，再输入完整文件名确认。服务端重新检查使用情况与记录版本，防止并发操作绕过检查。
- 清理失败保留持久删除标记，可从回收站重试；此时禁止恢复或继续引用。不会自动定时清空回收站。
- 复用不会复制文件内容；自行重复上传目前仍会产生独立文件，不宣称提供内容哈希自动去重。

项目「背景与封面」新增极光、晚霞、星夜、森林、海洋和沙丘六组原创预设。生成图片后按现有上传流程选择保留原图或 WebP，并可在其他项目复用。网盘上传沿用全站图片格式选择、传输进度及处理状态。列表使用受限尺寸的服务端栅格缩略图，不直接加载每张原图。

设计参考 [Misskey 文件浏览器](https://github.com/misskey-dev/misskey/blob/d9b1fc50ad4d57f708b9d6bc6fa7a763bb18602f/packages/frontend/src/components/MkDrive.vue)的文件卡片、分类导航和选择模式，以及 [DriveService](https://github.com/misskey-dev/misskey/blob/d9b1fc50ad4d57f708b9d6bc6fa7a763bb18602f/packages/backend/src/core/DriveService.ts)的文件归属校验。此处按 Vikunja 的任务权限、数据库与 API 客户端重新实现；回收站和引用保护是本分支新增行为，不照搬 Misskey 的删除方式。

升级会增加 `drive_files` 表。上线前应备份数据库和上传目录；旧版二进制不知道网盘保留规则，回退时必须恢复对应备份，不应直接用旧版继续操作新版数据。


## 可重放的界面引导

首次登录进入总览时，会出现可关闭的教程提示。点击右上角 **问号图标 → 帮助与引导教程**，或使用头像菜单中的同名入口，可以随时选择、重放三组高亮教程：

- **基础使用（9 步）**：总览、项目、快速添加、日期与时间段、团队协作、搜索、AI、个人设置和帮助入口。
- **AI 与语音（7 步）**：模型连接、协议与端点、获取或手填模型、功能分工、保存测试、权限和语音输入。
- **公开展示（6 步）**：发布状态、可联系时段、别名和隐藏规则、自定义正文、预览与发布。

教程会前往相关页面，但不会自动编辑、保存、发起 AI 请求、录音或发布内容；开始前请保存正在编辑的表单。支持上一步、下一步、跳过、键盘左右键、Esc 退出和完成后重放。手机上按步骤展开或收起侧边栏，说明卡片适应屏幕并可滚动；不可用的区域会给出继续或退出提示。

首次提示和完成状态按 **API 服务地址 + 用户账号** 记录在当前浏览器，本地存储被禁用时仍可使用教程。公开访客页、分享访客页和登录页不显示私人工作台教程。图标沿用 Font Awesome SVG，设置菜单、AI、语音和公开主页的主要操作补充了图标。

## 保存会话的任务助手

进入侧边栏 **AI 任务助手**。左侧新建、选择、重命名或删除会话；消息支持 Enter 发送、Shift+Enter 换行、复制 Markdown 回答和停止执行。默认只读，可为每次请求选择模型、项目及操作权限。

- **流式与后台执行**：文字模型默认请求流式响应，可在连接设置勾选“使用非流式响应”关闭。浏览器通过账户鉴权 SSE 接收实时状态，断线会自动重连，必要时回退查询；离开页面、切换会话和关闭浏览器不会取消服务器任务，只有主动停止才取消。服务器重启仍会将未完成任务标为中断，不会擅自重试。上游忽略流式请求而返回 JSON 时会如实提示。
- **真实过程**：展开“思考与执行步骤”实时查看服务商主动返回的思考文字或思考摘要、每轮模型请求、正在接收的工具参数、执行收据、真实结果及耗时。工具参数草稿在模型完整返回并通过服务器校验前不会执行。服务商实时报告用量时同步显示；尚未报告时显示等待用量及已接收字符数，字符数不是 token 估计。服务商没有返回时明确提示未提供；签名和加密推理上下文仅在服务器保存，不作为可读思考内容展示。
- **请求详情**：显示请求和实际返回的模型、协议、端点、当轮实际系统提示词、输入/输出/缓存/思考 Token、总耗时、首个 Token 和首段回答时间。用量来自服务商，不进行估算；缓存及思考 Token 已包含在输入或输出中。首个 Token 以首段流式文字或思考为准，非流式响应不伪造首字时间。
- **压缩上下文**：至少一轮后可使用当前模型总结当前整个会话，生成供下一轮复用的上下文检查点，涵盖目标、约束、具体 ID/日期、已完成操作、失败/拒绝/未知结果和待办事项。长会话分批滚动总结；保留全部界面原文，后续请求使用最新检查点和检查点之后的新消息。压缩本身作为后台任务运行，可查看摘要草稿、主动停止；失败保留上一份检查点。压缩仅总结，不执行任务工具，仍消耗模型用量。
- **创建分支**：从某条回复复制到该处的历史及模型上下文，原会话保留。分支不会回滚或重做真实任务操作。
- **可靠续用**：会话绑定当前账户，服务器加密保存。页面刷新后可恢复查看进行中的执行。服务重启会把未完成请求标为中断，不会自动重试；相同请求编号仅允许重试相同消息，防止重复操作。

连接测试现在使用与助手相同的只读工具参数，并通过合成结果检查工具续接，不读取或修改真实项目。模型未调用工具时明确说明续接尚未验证。DeepSeek Anthropic 地址 `https://api.deepseek.com/anthropic` 可直接填写；空的工具 `required` 字段按 JSON Schema 发送 `[]`。

会话与完整模型上下文位于持久文件目录 `.tcymc-ai/conversations/<用户ID>/`，AES-GCM 加密、目录权限 0700、文件权限 0600。备份时连同 `VIKUNJA_SERVICE_SECRET` 保存。每账户最多 100 个会话、每会话 200 轮，单个加密记录上限 16 MiB；达到限制后新建或删除旧会话。每账户同时运行一个助手请求。切换模型或协议后以纯文字和真实操作记录续接，避免把旧服务商的签名上下文发给另一服务商。会话接口不接受 API Token、公开分享或机器人身份，也不暴露到 MCP。

## 可审核、可继续的 Agent 执行

在助手的“上下文与权限”里选择工作模式和审核策略：

| 策略 | 普通单项修改 | 原子批量修改 | 删除、新建项目、评论、负责人变更 |
| --- | --- | --- | --- |
| 智能审核（默认） | 自动执行 | 展示整批预览 | 展示预览 |
| 逐项审核 | 展示预览 | 展示整批预览 | 展示预览 |
| 自主执行 | 自动执行 | 自动执行 | 展示预览 |

默认仍为只读；删除工具需要另行勾选。审核由服务器控制，不依赖模型自行判断风险。卡片展示真实记录的修改前后值、具体参数和快照；可以批准、拒绝、编辑 JSON 并更新预览。编辑后必须审核新的预览编号。拒绝结果会反馈给模型，模型可继续完成其余部分。`ask_user` 用于真正缺少目标或日期等信息的澄清，支持候选选项与自由回答。

“当前项目”提供上下文；“仅允许修改这些项目”才是硬性写入范围。选定范围后，后端逐次检查目标项目，跨范围修改和新建项目被拒绝。任务详情可通过“交给 AI 助手处理此任务”进入带任务 ID 的会话入口，不自动读取或发送任务正文。

任务修改和删除会在事务内锁定记录，再检查实时权限与审核快照版本。只更新明确指定的字段，保留其余内容；任务状态在审核期间变化会生成新预览。批量修改最多 25 个不同任务，任一项失败整批回滚。返回业务层实际结果，包括重复任务完成时的日期处理；不会把拟修改值当成实际结果。

默认每段允许 **16 轮模型请求、40 次操作、180 秒活动执行时间**；界面可分别配置 1–40 轮、1–100 次、1–600 秒及 token 软上限。批量按任务数计入操作预算，工具发现也计一次。到达预算会保存当前位置，可明确追加一段预算后继续；最多累计 200 轮、1000 次操作。token 仅按服务商报告的用量在请求之间检查，单次请求可能超过软上限。审核等待不占执行时限。

暂停状态、原生模型上下文和每次操作收据均加密保存，审核后可从保存位置继续。刷新或正常审核续接不会重放已完成的工具。服务重启时正在执行的请求标为中断；未确认结果的写入标为未知，必须先核查真实记录。文件收据与数据库提交并非跨系统原子事务，因此不声称崩溃时能够保证恰好执行一次。

工具定义、参数验证、能力发现共用同一份 JSON Schema；日期、范围和未知字段也由服务器校验。模型收到具体错误后可修正参数，权限与范围错误不会获得额外权限。模型理解仍可能出错，任务结果和操作收据才是判断执行情况的依据。

## 交互、配色与图片上传

助手支持实时阶段、模型用量、工具草稿和执行进度，消息与按钮采用轻量弹性过渡；遵循系统“减少动态效果”设置。流式更新保持阅读位置，滚动到底部后才继续跟随。手机可使用会话侧栏、输入区和上传选择窗口。

空项目列表点击“新建任务”会滚动到输入框、聚焦并显示高亮和输入提示。通用颜色选择器提供 **64 色、4 组方案**（鲜明、柔和、大地、灰阶），原有自定义颜色仍可用。

**项目设置 → 背景** 中上传的图片也作为项目卡片封面，设置页提供预览。通过站点 SDK 上传图片时统一选择：

- **原图**：默认选项，保留实际文件字节；头像可先选择方形裁剪，勾选裁剪会改变原始图片。
- **WebP**：在本机转换静态 PNG/JPEG/WebP/BMP，可选质量和最长边，然后再上传，避免多传大图。GIF、SVG、TIFF 等格式保留原文件，界面明确提示；背景和头像仍按服务器允许的栅格格式校验，不接受 SVG。
- **进度**：统一显示准备、转换、上传、服务器处理和完成/失败。上传百分比来自浏览器发送字节进度；转换和服务器处理没有可信总量时显示不定进度。上传完成与服务器处理完成分开显示。

头像、项目背景、任务附件和编辑器图片共用传输层；非图片附件同样显示上传进度。图片仍受原有大小、解码像素及并发限制约束，旧客户端未提供格式选择时保留原有服务端转码行为。语音转换和识别也显示进行中的阶段。

会话事件与压缩检查点的设计参考 [Codex app-server 的事件生命周期](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/app-server/README.md)、[Codex compact.rs](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/compact.rs) 和 [OpenAI Compaction 文档](https://developers.openai.com/api/docs/guides/compaction)。本项目用通用模型摘要实现跨协议检查点，没有调用仅面向 Responses 的加密 compaction 协议，也不会展示模型未返回的私有推理。

## 报错与调试窗口

入口：**头像菜单 → 报错与调试**，或助手页面顶部同名按钮；错误通知也提供打开入口。每条助手回复的“查看运行诊断”可打开该轮记录。支持 HTTP/代理错误、浏览器错误与助手执行记录，默认只在当前浏览器内存保留最近 30 条，重复请求错误合并计数，刷新、清空或切换账户后移除。保存在会话中的运行记录可重新打开诊断。

报告提供版本、时间、页面路径、HTTP 状态、追踪编号、错误阶段、协议、请求及实际模型、真实端点、token、耗时、首字时间、预算和工具状态。复制和下载 JSON 都会先展示预览，不会自动上传。

默认导出不含对话正文、工具参数或结果。需要定位模型参数等具体问题时，可勾选“附带具体报错、工具参数和结果”，检查预览后再分享。请求头、登录令牌和原始音频不收集；敏感字段、常见密钥格式以及 URL 凭据与查询参数会脱敏。自由文本仍可能含私人内容，分享详细报告前应自行检查。代理返回 HTML 拦截页时展示简明提示，不再把整页 HTML 塞进错误通知。

执行设计参考了 [Home Assistant 的 LLM 工具边界](https://github.com/home-assistant/core/blob/d40f18cc477d3bd0c39dfdec331c0096f7dcdddd/homeassistant/helpers/llm.py)、[n8n 工具审核](https://github.com/n8n-io/n8n/blob/7fc63ed7f7ec9c619825b95e999cf9b968aa4823/packages/cli/src/tool-generation/hitl-tools.ts)、[OpenHands](https://github.com/OpenHands/software-agent-sdk)、[LibreChat](https://github.com/LibreChat-AI/LibreChat)、[CopilotKit](https://github.com/CopilotKit/CopilotKit) 与 [LangGraph](https://github.com/langchain-ai/langgraph) 的能力发现、交互式审核和暂停恢复思路，使用本项目现有 Vue、Go 与权限模型实现，没有引入这些项目的运行服务。

## 对话场景与按需工具加载

助手采用居中的对话阅读区、底部自适应输入框、可收起的历史记录，以及独立的“场景与偏好”面板。输入区直接切换查询与建议、计划与审核、日常管理和批量整理；每项权限、预算都有说明。可保存最多 20 个个人模板并设为账户默认，模板不含密钥或对话内容。取消设置不影响当前选项；修改仅作用于下一次发送，正在运行的后台任务保持原设置。模板保存在服务器加密设置中，独立接口和 revision 冲突检测防止覆盖模型密钥及其他窗口的更新。

工具发现参考 [Anthropic 的高级工具使用设计](https://www.anthropic.com/research/advanced-tool-use) 与 [Tool Search 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)。本项目在执行层实现跨协议的按需加载，不要求兼容服务实现 Anthropic 专属工具搜索 API，也没有引入其他 agent 运行服务：

- 每次新请求从 5 个常驻工具开始（项目查询、任务查询、任务读取、能力发现、询问用户），写入及扩展能力通过 `find_tools` 加载。
- 优先匹配精确工具名，仅搜索能力名称和说明，每次最多 5 个；保留最近 8 个扩展工具及尚未执行完的调用。工具缺失时可再次发现，权限和参数仍由服务端验证。
- 发现结果只返回简短目录，完整参数定义仅放进后续请求的工具声明。重放旧会话时也会精简旧版发现结果中的重复定义，原始记录保持不变。
- 每轮记录实际加载的工具名、数量和规范 JSON 的 UTF-8 字节数，供步骤详情和诊断使用。字节数不是 token 估计，也不能直接推算账单；实际 token 仍以服务商报告为准。

## AI 与语音

登录后进入 **设置 → AI 与语音**，添加连接名称、HTTPS API 基础地址、API 密钥、模型 ID、用途与协议。基础地址包含服务商要求的版本路径，不要填写具体请求端点。例如 OpenAI/Anthropic 通常使用 `/v1`，Gemini 通常使用 `/v1beta`；代理服务以其文档为准。页面会展示完整的模型调用端点和模型列表端点，连接测试成功后也返回服务器实际使用的端点。

三个功能独立分配模型：**语音识别 → 识别文字整理 → 任务 AI 助手**。支持的协议如下：

| 协议 | 可用功能 | 在基础地址后追加的路径 |
| --- | --- | --- |
| OpenAI Chat Completions | 文字整理、任务助手 | `/chat/completions` |
| OpenAI Responses | 文字整理、任务助手 | `/responses` |
| Anthropic Messages | 文字整理、任务助手 | `/messages` |
| Gemini | 文字整理、任务助手、语音识别 | 默认 `/models/{model}:streamGenerateContent?alt=sse`；非流式 `/models/{model}:generateContent` |
| OpenAI Audio Transcriptions | 语音识别 | `/audio/transcriptions` |
| OpenAI Chat Audio | 语音识别 | `/chat/completions` |

**获取模型列表**会使用对应协议的鉴权访问上游 `/models`，支持 Anthropic/Gemini 分页（最多 10 页），并按名称去重排序。可以在保存前获取，已保存的同一地址可复用密钥。模型 ID 始终允许手动输入；上游未提供列表或列表获取失败，也能继续配置。列表只表示上游列出的模型，使用语音或任务工具仍需选择支持相应能力的模型。Anthropic Messages 不提供原始音频输入，不能作为语音识别连接；可以处理识别后的文字。

点击保存后可以测试连接。语音测试需上传音频。AI 助手支持浏览器录音（最长 3 分钟）或上传音频（最大 16 MiB），识别后可修改文字，再明确发送执行。OpenAI Chat Audio 需要支持音频输入的模型；WAV/MP3 直接发送，浏览器录音等格式在本机转为 16 kHz 单声道 WAV（转换最长 3 分钟）。Gemini 内嵌音频限 14 MiB，以控制 Base64 后的请求体积。浏览器需要 HTTPS 和麦克风权限。

协议参考：[OpenAI 音频对话](https://developers.openai.com/api/docs/guides/audio-chat-completions)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini 音频输入](https://ai.google.dev/gemini-api/docs/audio)。

Responses 的工具调用与推理上下文、Anthropic 的工具结果、Gemini 的函数调用和 thought signature 都按各自原生结构处理。历史版本的连接会自动按原来的 OpenAI 兼容协议读取。

助手支持项目、任务、绝对提醒、标签、评论、负责人、任务关系与原子批量排期。基础工具始终可用，扩展工具通过 `find_tools` 按需发现、加载；未加载或不在当前读写权限内的工具会被拒绝。所有操作继续调用 Vikunja 原有权限与业务规则。内置助手不管理账户、密钥、分享权限、任意 SQL 或任意外部请求。

密钥仅写入，读取设置只返回是否已配置。模型配置按用户存储在 `files/.tcymc-ai/`，使用服务端 `service.secret` 派生密钥进行 AES-GCM 加密；**备份与恢复必须同时保留 files 和 service.secret**。默认限制模型地址为可公开路由的 HTTPS 服务，沿用上游出站请求 SSRF 防护。开发机如需访问私有模型，应由服务器管理者审查并配置上游 `outgoingrequests` 选项。

AI 收到的是本次对话及工具查询到的任务数据，使用前应选择你信任的模型服务。调用失败可能已有部分操作完成，请先查看执行记录和任务状态。会话请求编号和操作收据持久保存，用于防止相同消息重复提交。旧 `/ai/run` 兼容接口仅提供进程内 10 分钟缓存；新界面使用可保存会话的接口。当前不预置任何真实模型账号或密钥。

上游 MCP 入口仍为 `/api/v2/mcp`。外部 agent 可在 **设置 → MCP** 创建具备所需权限的令牌；自定义 AI 设置和公开主页管理接口只允许本人登录会话使用，不向 MCP 提供。

## 公开主页与忙闲时间

进入 **设置 → 公开主页**，填写地址、标题、简介、可联系星期/时段与展示天数（1–31 天）。默认未发布、没有公开项目。

1. 只添加你愿意公开的项目，设置对外别名。默认显示“忙碌”，不暴露项目和任务原名。
2. 可选择公开任务标题，或完全隐藏项目。预览后可以给单个任务设置别名或完全隐藏。
3. 编辑 Markdown 或静态 HTML 正文。可用 `{{schedule}}`、`{{availability}}`、`{{projects}}` 插入经过发布规则处理的内容。
4. 可勾选完全自定义正文，隐藏默认日程面板。HTML 使用隔离 iframe，可内联 CSS；脚本、表单和访问主应用的能力不可用。
5. 点击 **预览公开效果**；修改内容后必须重新预览，才能点击 **发布当前预览**。

网页入口：`https://你的域名/p/页面地址`。机器人入口：`GET https://你的域名/api/v2/public/页面地址`，无需登录，返回 `title`、`intro`、`content`、`format`、`projects`、`events`、`free`、时间范围与生成时间。

机器人请求示例：`curl -A "VikunjaX-ScheduleClient/1.0" https://你的域名/api/v2/public/页面地址`。若部署在 Cloudflare 后面，现有防护规则可能拦截 Python 默认 User-Agent；为客户端设置明确的名称，并根据自己的规则配置 API 访问。

公开 JSON 使用与网页相同的披露规则，不含内部 ID、任务描述、成员、原始名称或私有编辑提示。自定义正文是你主动发布的内容，其中写入的信息也会公开。隐藏默认面板只改变页面排版，不改变 JSON 的公开范围。

**保存草稿不会修改已发布页面。** 发布后，日程按照上一次发布的规则随任务实时更新；页面每分钟刷新，接口每次请求重新计算。撤下页面会同时撤下 JSON。项目访问权限失效时页面停止返回日程。当前每个账号有一份公开主页，支持独立地址、滚动展示窗口与任意静态正文。

忙闲计算使用 **Asia/Shanghai**：有完整开始/结束时间的未完成任务形成忙碌时间段；仅有截止时间的任务作为截止事项展示，不占用整天。重叠时间段合并后从可联系窗口中扣除。隐藏或未选择的项目/任务不参与计算，因此这里的“可联系时间”仅代表已公开安排，不是完整私人日历或预约保证。用户可把敏感安排设为“忙碌”保留占用时间，避免暴露原名。

## 构建与 Docker 部署

```sh
git clone https://github.com/KanameMadoka520/vikunja-x.git
cd vikunja-x
docker build -f Dockerfile.tcymc --build-arg RELEASE_VERSION=v2.7.1-tcymc.5 -t vikunja-x:v2.7.1-tcymc.5 .
```

`Dockerfile.tcymc` 固定基础镜像摘要，使用锁定依赖构建前端，并生成带 SQLite 支持的静态 Go 二进制，最终以 UID 1000 在最小镜像中运行。提供 CA 和时区数据。数据库支持沿用上游，包括 PostgreSQL。

最小运行示例（生产可按上游文档接入 PostgreSQL）：

```sh
mkdir -p data/files data/db
sudo chown -R 1000:1000 data
docker run -d --name vikunja-x --restart unless-stopped \
  -p 127.0.0.1:3456:3456 \
  -v "$PWD/data/files:/app/vikunja/files" \
  -v "$PWD/data/db:/db" \
  -e VIKUNJA_SERVICE_PUBLICURL=https://task.example.com/ \
  -e VIKUNJA_SERVICE_SECRET=替换为随机且持久保存的长密钥 \
  -e VIKUNJA_SERVICE_ENABLEREGISTRATION=false \
  -e VIKUNJA_SERVICE_TIMEZONE=Asia/Shanghai \
  vikunja-x:v2.7.1-tcymc.5
```

通过反向代理提供 HTTPS。创建首个账号使用 `docker exec -it vikunja-x /app/vikunja/vikunja user create --help` 查看 CLI 参数。注册默认建议关闭；SMTP 初始使用上游 `VIKUNJA_MAILER_*` 配置，也可通过上述管理员页面保存；密码勿提交源码。账号名中的 admin 不会绕过上游授权功能。

Release 附带 Linux amd64 二进制、Docker 镜像包及 SHA256 校验文件；使用 `docker load -i vikunja-x-v2.7.1-tcymc.5-linux-amd64.docker.tar.gz` 导入镜像。
