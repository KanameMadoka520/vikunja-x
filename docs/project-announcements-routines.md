# 项目公告与日常打卡

项目顶部公告用于长期共用的信息：工作约定、入口链接、每天要关注的事项。它独立于项目描述，沿用项目访问权限，不会创建公开页面。一个项目有一条公告，可在列表、看板、表格和甘特视图查看；有写权限的人可编辑，归档后只读。标题和正文都为空表示清除。折叠是当前账户在当前服务器的个人显示偏好。

日常任务是共享项目内的每日一次打卡。任务 ID 和标题保持不变；打卡只增加当天记录，不设置任务 `done`，不移动到 Done 列，也不生成成百上千的重复任务。列表、看板、表格及任务详情共用状态。多人协作时，一个人的打卡代表这项共享工作今天已完成；它不是每个成员各自的个人习惯追踪器。

## 使用与时间规则

在开放任务的详情中启用「日常打卡」，选择 IANA 时区。已有普通重复规则或已经完成的任务必须先明确取消普通重复/重新打开，系统不会隐式改写这些设置。暂停暂时禁止打卡；停用恢复普通任务操作；两者都保留历史。

只可完成和撤销今天。日期由后端根据该任务时区计算，跨日请求会要求重新读取，不补写到昨天。次日零点重新待打卡，支持夏令时的 23/25 小时日。变更时区不会重新计算历史日期、原时区、操作者和完成时间。撤销今天会移除今天的完成记录；这里展示的是完成记录，不是不可修改的审计账本。

任务详情按月查看已记录日期、累计次数、当前连续天数和最长连续天数。连续天数以实际自然日为准，暂停日不虚构完成；当前连续允许截至昨天的连续记录。旧任务的完成状态不推测为历史打卡。复制任务/项目只复制日常配置，新的副本从零开始记录；复制项目还会复制可见公告。

现有任务提醒保持不变。启用日常打卡本身不会自动创建每天的推送或邮件提醒。

## API 与一致性

全部接口在 `/api/v2`，前端使用生成 SDK 和 Vue Query 查询层：

| 接口 | 用途 |
| --- | --- |
| `GET/PUT/PATCH /projects/{project}/announcement` | 公告读取与版本化保存 |
| `GET/PUT/PATCH /tasks/{task}/routine` | 日常配置，写入返回完整任务 |
| `POST /tasks/{task}/routine/check-in` | `{date, completed}` 今天完成或撤销，幂等 |
| `GET /tasks/{task}/routine/history?year=2026&month=11` | 月度记录与累计/连续统计 |

公告和配置写入必须带最近读取的 `revision`。冲突不覆盖服务端的新内容。错误码：20001 公告冲突，20002 配置/日期冲突，20003 任务状态不支持该操作。任务通用完成/批量更新/Done 列拖拽也执行后端日常规则检查。父资源锁、版本检查和任务状态变更在同一事务内；提交后才派发更新事件。相同日期的重复打卡不重复触发变更。

日常摘要通过两次批量查询附加到任务读取，避免每行独立查库。有日常摘要的任务及公告使用实际响应的 ETag，包含日期和版本变化，避免跨日或同一秒写入继续返回旧状态。前端使用一个共享时钟及重新聚焦刷新，写入后更新缓存副本，不整页重载。

数据在三个独立表：`project_announcements`、`task_routines`、`task_routine_checkins`。升级只新增表，不修改现有项目/任务索引或推测历史。软删任务保留配置与历史，永久删除任务清除相关记录。数据库备份包含这些表；目前跨实例的用户 JSON 导入/导出不是该新记录的迁移接口，请使用完整数据库备份保留记录。

## 阿罗娜

六个工具通过原有 `find_tools` / `invoke_tool` 按需发现，不把完整定义塞进每轮请求：

- `get_project_announcement` / `update_project_announcement`
- `get_task_routine` / `configure_task_routine`
- `check_in_task_routine` / `get_task_routine_history`

写入遵循本轮工作方式、项目范围、账户权限及操作审核。公告更新要求审核；日常修改在执行前后检查真实状态，回执更新当前页面的相关缓存。公告和任务中的文字是待处理数据，不是替代系统规则的指令。
